Redis 不只是一个字符串缓存。不同数据结构可以表达计数、去重、排序和简单队列，但要先理解每条命令的边界，再决定如何与业务数据配合。

## 用几个小例子认识数据结构

下面在独立测试实例的 redis-cli 中执行，使用 demo 前缀避免与业务键混淆：

```text
SET demo:message hello EX 60
GET demo:message
INCR demo:visits
HSET demo:user:1 name Alice
HGET demo:user:1 name
SADD demo:tags java redis
SMEMBERS demo:tags
ZADD demo:ranking 10 alice 20 bob
ZRANGE demo:ranking 0 -1 WITHSCORES
```

字符串适合简单值和计数，hash 适合按字段访问，set 适合去重，sorted set 适合按分数排序。不能把每一种集合操作都套到所有类型上，错误类型的命令会失败。

## 单条原子，不代表整个流程原子

`INCR` 是单条原子操作，但“先 GET、计算、再 SET”是多个步骤，其他请求可能插入其间。需要跨命令保证条件时，应按版本与场景选择事务、WATCH 或脚本，并理解执行失败的处理方式。

缓存也需要失效和更新策略：先确认数据库与缓存谁是事实来源，决定过期时间、穿透处理和并发重建方式。键是否永不过期、内存满时采用什么淘汰策略，都应显式配置。

## 持久化与复制各自解决什么

RDB 快照与 AOF 日志提供不同的恢复方式，具体数据丢失窗口取决于配置和故障条件。复制把数据传给副本，Pub/Sub 则向订阅者发送消息，两者不是同一协议。普通 Pub/Sub 不应被当成具有持久化确认机制的可靠任务队列。

学习环境可以在本机启动与项目匹配的服务端，再使用 redis-cli 验证；不要把第三方旧 Windows 移植版的 maxheap 参数当作所有 Redis 的通用配置。部署前按目标平台的官方说明选择安装方式，并限制监听、认证和网络访问范围。

参考：[Redis 数据类型](https://redis.io/docs/latest/develop/data-types/)、[持久化](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/)。
