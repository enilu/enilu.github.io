让 AI 改一个功能，通常不止是在聊天框里发一句要求。你还要选择项目和分支，看它改了哪些文件，运行测试，打开页面确认效果；如果同时做几件事，就得在几个终端和会话之间来回切换。

Paseo 把这些环节组织在一个工作台里：底层使用已经安装的编码 Agent，上层提供项目、工作区、会话和结果查看，也能从手机接入同一个开发现场。前面写[开发工具选型与打磨](/学习笔记/2026/10/22/AI时代我的开发工具选型与打磨)时提到过它，这次主要从功能和场景展开，最后再介绍我做的一些定制。

## 一个工作台，连接多种编码 Agent

Paseo 支持 Claude Code、Codex、GitHub Copilot、OpenCode、Pi 等编码 Agent，提供桌面、手机、Web 和 CLI 入口。创建任务时选择已经配置好的执行者和模型，就能在相同的界面里查看它们的工作。[官方项目说明](https://github.com/getpaseo/paseo)

对我来说，这个能力最实际的用途，是按任务的重要程度和投入成本选择 Agent 与模型。我现在主要这样分配：

| 任务场景 | 使用的 Agent 与模型 | 选择时关注什么 |
| --- | --- | --- |
| 工作中的开发任务等重要工作 | Codex + GPT-6.1 | 更看重实现质量、复杂问题的处理和交付验证 |
| 给孩子做在线小游戏、教育类工具等轻量任务 | OpenCode + DeepSeek（付费） | 兼顾效果和调用成本，方便围绕小功能反复调整 |
| 轻量尝试和原型探索 | OpenCode + 可用的免费模型，例如使用过的 Space Bunny（太空兔） | 用较低成本试想法，先做出可操作的版本 |

这里有三层需要分清：**Paseo 是工作台，Codex 和 OpenCode 是执行任务的 Agent，GPT-6.1、DeepSeek 等则是 Agent 调用的模型。** 因而，使用 DeepSeek 时，是先在 OpenCode 里配置模型服务，再通过 Paseo 使用这个 Agent；DeepSeek 官方也提供了 [OpenCode 接入说明](https://api-docs.deepseek.com/quick_start/agent_integrations/opencode/)。

这样的安排让我能保留同一套项目和工作区入口，根据任务调整底层组合。工作中的开发任务优先使用 Codex 的 GPT-6.1；给孩子做小游戏或教育工具时，则更多使用 OpenCode，选择付费 DeepSeek，或者尝试当时可用的免费模型。这里记录的是我的使用分工，不是模型能力排名；免费模型的名单、额度和可用性也会变化，以实际服务为准。

各 Agent 的工具、权限和历史格式仍有差异，切换执行者不会自动继承所有上下文。交接时，代码、任务说明和验证记录仍然有用。

它的基本结构也很清楚：**daemon 在开发机器上管理 Agent 进程，客户端负责展示和交互。** 机器可以是自己的电脑，也可以是自己维护的服务器。任务在哪里执行、依赖安装在哪里、文件保存在哪里，都由 daemon 所在的环境决定。

自托管让它能复用自己的工具和开发环境；模型调用仍按 Agent 配置进行，并不自动变成离线推理。

## 同时推进两项任务，先给它们各自的工作区

假设一个项目同时要增加列表筛选和修复导出问题。两项工作需要分别修改、验证，又希望能同时推进。

Paseo 用工作区组织任务。工作区里可以放 Agent 会话，也能围绕同一份代码查看文件、差异和运行结果。对于独立改动，可以用 Git worktree 为任务建立单独的工作目录和分支。

一个具体的使用过程是：

1. 为列表筛选新建工作区，选择项目、起始分支，以及 New worktree 隔离方式。
2. 再为导出问题创建一个工作区，从同一个基础分支开始。
3. 分别选择 Agent，说明修改范围和验证要求，让两个任务并行运行。
4. 在侧栏切换工作区，检查进度、补充要求，最后分别审查和合并。

同一种 Agent 可以同时处理两个任务，也可以选择不同的执行者。对于同一个需求，还可以在两个工作区尝试不同实现，再比较方案。[官方并行开发指南](https://paseo.sh/docs/parallel-development)

这里要分清工作区与会话：同一工作区里的多个 Agent 共享工作目录。如果希望它们独立修改代码，需要安排各自的 worktree；如果只是让第二个 Agent 审查当前差异，可以留在同一现场，并明确要求不改文件。

worktree 隔离了文件和分支，服务仍共享机器资源。例如两份前端同时启动开发服务，需要分配不同端口。

## 从“它说完成了”，走到自己能检查结果

Agent 输出“已经完成”以后，还需要检查差异和运行验证。Paseo 把这些入口与会话放在同一个工作区里。

在桌面端，可以打开 Changes 看 diff，通过 Files 浏览和编辑文件，把会话和代码并排摆放；需要验证时，再打开该工作区的终端运行项目命令。这样，追问“为什么改这一段”时，眼前有实际改动可以对照。

对于 Web 项目，还可以在桌面工作台里打开浏览器页签，访问开发服务。配置好浏览器自动化后，也可以要求 Agent 按指定步骤检查页面。相比只告诉它“测一下”，说明访问地址、操作步骤和预期结果更容易得到可核对的输出。相关入口见[并行开发指南中的审查与运行流程](https://paseo.sh/docs/parallel-development)。

例如，列表筛选任务结束后，先检查请求参数和状态管理的 diff，再运行相关测试，最后打开页面确认筛选与清空行为。这个流程并不要求所有步骤都交给 AI；工作台让人和 Agent 围绕同一份结果继续讨论。

## 离开电脑以后，用手机接着看同一个任务

跨设备访问是 Paseo 很有辨识度的用途。Agent 在电脑或服务器上继续运行，手机作为客户端接入，查看同一个任务的输出，必要时补充要求或处理交互。

例如，在桌面端发起一项耗时任务后，离开电脑时用手机确认进度；发现 Agent 对需求理解偏了，可以继续发消息说明。手机访问的是原来的执行环境，无需再拉取仓库、安装依赖，也不会因为换了屏幕就新开一套项目现场。

官方提供 Relay、Tailscale 等连接方式；桌面和 CLI 还可以通过 SSH 连接已有 daemon。Relay 需要主动启用，连接流量采用端到端加密；不同客户端可用的接入方式和配置步骤见[连接文档](https://paseo.sh/docs/connectivity)。

原机器仍需在线。手机适合查看进度和补充指令，大段 diff 审查或复杂调试则更适合桌面。

## 语音、定时任务和 Agent 协调，让入口更灵活

在手机上组织一段较长需求时，语音输入很实用。Paseo 提供听写和语音对话模式：前者把讲话转成输入，后者用于围绕编码环境进行语音交流。语音链路可以选择本地模型或云端服务，识别语言与所选模型有关；中文使用时应确认模型的语言支持。[语音文档](https://paseo.sh/docs/voice)

语音适合描述背景和补充思路，涉及路径、接口字段或具体命令时，应检查转写结果。

重复性工作则可以使用 Schedules。它按设定的节奏，在指定仓库和 Agent 配置下发起新任务；Heartbeat 面向已有会话，定期提醒它重新检查状态、继续推进。例如，每天整理一次待处理问题适合新任务，持续跟进某次构建更接近已有会话的周期检查。[定时任务文档](https://paseo.sh/docs/schedules)

再往前一步，Paseo 还提供 Agent 协调能力。启用相应工具后，一个 Agent 可以创建其他 Agent、分配研究或审查任务、查看进度并收集结果；CLI 也提供相应操作。它适合有明确分工的任务，比如实现完成后再请另一个 Agent 独立审查，而不必每次由人手工搬运要求。[Agent 协调文档](https://paseo.sh/docs/orchestration)

## 我的个人版本，主要补了三类日常需求

上面介绍的是 Paseo 本身的功能和使用方式。我的 fork 主要围绕访问、分享和结果交付做了一些调整。

### 项目和工作区访问码

个人版本给项目和工作区分别加了访问码。项目名称仍可见，解锁后才能查看其工作区或新建工作区；工作区标题仍可见，查看时间线、继续对话和创建 Agent 则需要解锁。

它适合在保留侧栏导航的同时，限制具体内容的访问。项目名称和标题并不会被隐藏，因此敏感信息也不应放在那里。这是实例内的访问控制，不等同于系统账号或执行环境隔离。

### 会话分享，以及主动开启的协作

为了把需求讨论、方案变化和最终结论交给别人看，我增加了加密会话分享。默认生成分享时刻的只读快照，接收者凭完整链接查看，无需登录 Paseo；后续对话不会自动更新到快照里。

分享内容在客户端加密，密钥放在链接的 `#` 片段中。完整链接本身包含解密能力，需要按内容敏感程度决定发给谁。分享时会过滤 shell 工具调用记录，但文字回复和其他结果仍可能带有代码或业务信息，不能把它当作完整脱敏。

如果需要对方继续参与，可以主动打开“允许协作”，默认关闭。开启后，分享页能读取指定 Agent 的时间线并向它发消息，服务端把权限限制在这个会话内；当前协作凭证有效期为七天，使用时原 daemon 和 Relay 链路需要可用。

这里的区别很实际：只读分享是请人看过程，协作是让人参与后续工作。消息可能让 Agent 修改代码或执行命令，所以允许协作时，也要考虑它原本具备的执行权限。实现可查看[分享创建逻辑](https://github.com/enilu/paseo/blob/suzhou/packages/app/src/agent-sharing/create.ts)。

### 文件交付与本机使用细节

文件预览增加了下载按钮，助手消息里的文件也补了跨传输方式下载处理。人在另一台设备上看完结果后，可以继续把文件保存下来。

Windows 方面，补了包含中文、空格和 URL 编码的文件链接处理，以及 Home 目录外精确绝对项目路径的支持。另有 Codex 原生历史显示开关、按最近活动排序工作区、保留提示词语言的标题，以及背景图和透明度等设置。

定制桌面包还可以关闭自动更新，配合手工维护的更新说明控制升级节奏。这些调整可以在[个人分支更新说明](https://github.com/enilu/paseo/blob/suzhou/packages/app/src/release-notes/release-notes.ts)和后续提交里查看；同步上游带来的能力仍归上游，不混在个人新增功能里。

## 从一个真实任务开始尝试

如果你经常使用多种 Agent、同时推进几项开发任务，或希望离开桌面后继续查看工作，Paseo 值得尝试。准备至少一个已经安装并完成认证的 Agent CLI，再从[官方桌面端](https://paseo.sh/download)或[入门文档](https://paseo.sh/docs)开始即可。

第一次可以选一个熟悉的仓库，完成一项小改动，再检查 diff、运行测试、查看效果。等这条工作链顺手以后，再增加并行任务和远程接入，判断它们是否减少了切换和恢复现场的成本。
