Nutz 的 JSON 模块既处理 JSON 文本，也处理 Java 对象的类型与字段。把解析和输出分成两条路径，更容易看清每一层在解决什么问题。下面以 1.b.53 为源码阅读基线。

## 从入口重载找到核心职责

```java
Map data = Json.fromJson(Map.class, "{\"name\": \"Alice\", \"age\": 18}");
String text = Json.toJson(data, JsonFormat.compact());
```

片段使用 org.nutz.json.Json、JsonFormat 和 java.util.Map。它展示文本到内存对象，再到文本的路径。fromJson 有 Reader、CharSequence 和目标 Type 等重载；Reader 负责输入来源，目标类型负责结果形状，两者是不同维度。

`fromJsonAsArray` 返回数组，`fromJsonAsList` 返回列表，不应因为它们都处理 JSON 数组就把返回类型混为一谈。带泛型集合时，还需检查元素类型信息如何传递，而不是只看外层 Class。

## 输出按类型分派

JsonRenderImpl 持有 Writer 与 JsonFormat，render 根据值属于 null、数字、布尔、字符、日期、Map、集合、数组或普通对象，进入不同输出路径。

数字和字符串即使显示内容相同，也有不同 JSON 类型。字符串还要转义引号、反斜杠和控制字符；日期如何输出则受格式策略影响。不能用对象的 toString 直接拼出所有 JSON。

## 关注字段元数据和引用关系

普通对象的字段访问经过 JsonEntity 等描述，字段名、忽略规则与自定义输出共同影响结果。容器和对象还可能共享引用或形成循环，输出行为必须结合该版本的 memo 与递归分支检查。

最小用例之外，应验证嵌套集合、空值、特殊字符及重复引用。文本往返一致也不等于 Java 类型完全保留：整数宽度、日期和自定义对象，仍依赖目标类型及转换规则。
